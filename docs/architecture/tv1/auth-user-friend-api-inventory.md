## Shared contract conventions

All endpoints below are **PROPOSED / PENDING OWNER APPROVAL** and owned by TV1. UUIDs and UTC timestamps are strings. Fields listed are required unless marked nullable or optional. Paging uses a bounded `limit`, optional opaque `cursor`, `items` and nullable `nextCursor`. Cursors must be bound to requester, direction/filter and authorized projection. Actor identity comes from the trusted server principal or route-specific proof, never a client-supplied sender or role. Distinguish self DTO from public DTO. A public DTO can expose only `id`, `displayName` and nullable `avatarUrl` where visibility permits.

Apply the common envelope `{code,message,requestId}` and avoid reflecting private inputs or hidden resource state. Use 400 for validation, 401 for invalid authentication, 403 for a safely disclosed permission denial, 404 for missing/concealed resources, 409 for authorized conflict, 429 with safe retry guidance, and 503 for unavailability. Apply conditional revisions/ETags where approved. Do not refresh on 403 or concealed 404. Retries must preserve idempotency identity and payload and must not invent proof of rollback. The security spec and transport addendum remain the primary descriptions for credentials and wire failure handling.

## Decisions and Day 1 handoff

- **TV1** proposes the Auth method, OTP/provider pilot, secure session runtime, trusted user projection, exact lookup and relationship semantics. Requires group review for wire and privacy policy. Preserve P0 auth, profile, block and i18n scope.
- **TV2** must confirm DIRECT eligibility and peer UUID handoff, refresh/replay and Messaging/WS effects of friendship and block changes. Supply full wire/register evidence by exact ref when available.
- **TV3** must confirm GroupDirectory and PeopleDirectory projections, membership policy and offline/cancel expectations. Verify shared backend baseline scope and Flyway V1 history before schema changes.
- The remaining endpoint names, response fields, 404/empty concealment, transition enums and server preference ownership are gates for production. The inventory can be reviewed in parallel with FIX1. It does not authorize Day 2, Phase 2 implementation, or merge of any Foundation PR.
